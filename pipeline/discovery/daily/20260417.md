## Novel Discoveries

### 1. /ultrareview — Cloud Multi-Agent Code Review
**File**: `pipeline/evaluation/pending/20260417-ultrareview-cloud-multi-agent-review.json`
**Type**: technique | **Version**: v2.1.111 (research preview)

Launches a fleet of Claude reviewer agents in a remote cloud sandbox to find and independently verify bugs before merge. Runs in background (5-10 min), reports only confirmed findings — eliminating false-positive noise. Works on local diffs or PR numbers. Costs $5-$20/review after 3 free runs. Fundamentally distinct from the local `code-reviewer` subagent: cloud infrastructure, multi-agent parallel runs, independent cross-verification.

**Priority**: High — direct complement to existing code-reviewer; different cost/depth tradeoff worth documenting.

### 2. /ultraplan — Cloud-Based Interactive Planning
**File**: `pipeline/evaluation/pending/20260417-ultraplan-cloud-interactive-planning.json`
**Type**: technique | **Version**: v2.1.91+ (research preview)

Transfers a planning task from the local CLI to a Claude Code web session. Plan drafts in the cloud; users review with section-level inline comments in the browser, then either execute on the web or "teleport" the approved plan back to the local terminal. Requires claude.ai + GitHub. Complements /ultrareview (plan → implement → review).

**Priority**: High — closes the local-only limitation of plan mode for projects requiring collaborative review.

### 4. backlog MCP — Persistent Cross-Session Task Management
**File**: `pipeline/evaluation/pending/20260417-backlog-mcp-persistent-tasks.json`
**Type**: mcp_server

24-tool MCP server with event-sourced storage (pure TypeScript, zero external deps) that persists tasks across session boundaries. Unlike TodoWrite (in-session only), tasks survive `/clear` and session end, enabling agent-to-agent handoffs. Could complement or replace the manual BACKLOG.md convention. Needs maintenance/star count verification before recommending installation.

**Priority**: Medium — genuinely novel persistence model, but needs NEEDS_RESEARCH validation first.
