## Novel Discoveries

### 1. `--bare` Flag for Headless Scripted Calls (v2.1.81) ⭐

**Type**: technique (version feature)
**Priority**: HIGH
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2181-2026-03-20-evaluation.json`

New CLI flag for `claude -p` scripted calls that disables all session-level overhead:

```bash
claude -p --bare "Summarize this file" --settings .claude/minimal-settings.json
```

**What it skips:**
- Hooks (SessionStart, UserPromptSubmit, PreToolUse, etc.)
- LSP (language server protocol)
- Plugin sync
- Skill directory walks
- Auto-memory (fully disabled)

**Requirements:**
- Requires `ANTHROPIC_API_KEY` or `apiKeyHelper` via `--settings`
- OAuth and keychain auth disabled

**Why this matters:**
- Current heartbeat/cron automation uses `claude -p` with full session overhead
- Every cron run triggers hooks, loads all skills, syncs plugins — most of which are irrelevant for scripted tasks
- `--bare` mode is the headless mode for CI/CD and programmatic pipelines — analogous to `CLAUDE_CODE_SIMPLE` for token efficiency, but for startup latency and session overhead
- Distinct from `CLAUDE_CODE_SIMPLE` (which restricts native tools) — `--bare` skips the entire session infrastructure

**Integration value**: Direct relevance to heartbeat pipeline. Discovery/evaluation cron jobs don't need hooks firing or skills loading. The `claude -p --bare` flag could reduce startup time and eliminate spurious hook side-effects in automation runs.

**Score estimate**: 82/100 — APPROVED
- Integration complexity: 85 (drop-in flag addition)
- Token efficiency: 80 (eliminates skill directory walk overhead)
- Capability expansion: 75 (specialized scripted mode)
- Maintenance: 90 (zero maintenance, official feature)
- Community validation: 80 (official Anthropic release)

### 2. `--channels` Permission Relay (v2.1.81, IMPROVEMENT)

**Type**: technique (version feature — IMPROVEMENT of v2.1.80 --channels push)
**Priority**: MEDIUM
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2181-2026-03-20-evaluation.json`

v2.1.80 added `--channels` as a way for MCP servers to push messages into Claude sessions (research preview). v2.1.81 extends this with a **permission relay** capability:

> Channel servers declaring the `permission` capability can forward tool approval prompts to your phone.

**What this enables:**
- A Claude Code session running headlessly on desktop (requiem) can forward permission prompts to a mobile device
- Approval/denial happens from phone; session continues on desktop
- Closes the "autonomous session interrupted by permission prompt" loop without requiring Auto Mode

**Relationship to existing:**
- Auto Mode (v2.1.76+, RESEARCH_PREVIEW): Risk-based auto-approval — doesn't reach out for confirmation
- `--channels` permission relay: Human-in-the-loop from remote device — confirmation still happens, just remotely

These are complementary strategies for the same problem. Auto Mode for low-stakes operations; permission relay for operations that need human sign-off but shouldn't block the session.

**Status**: Still research preview. Monitor for stable release. No immediate integration action.

**Score estimate**: 72/100 (IMPROVEMENT, deferred — research preview)

### 6. Godogen — Domain-Specific API Reference Pattern ⭐

**Type**: skill/technique
**Priority**: MEDIUM
**Source**: https://github.com/htdt/godogen
**HN thread**: https://news.ycombinator.com/item?id=47400868

A Show HN post from 2026-03-20 presenting `htdt/godogen` — a set of Claude Code skills for generating complete Godot 4 games from a text description. The repo itself (game generation) is domain-specific and not relevant. But the **engineering pattern** it demonstrates to solve a training data gap is novel and transferable.

**The pattern: "Thin Training Data Compensation via Lazy-Loaded Domain Reference"**

The author faced LLMs hallucinating invalid GDScript (Python-like syntax with 850+ classes that Claude doesn't know well). Their solution:

1. **Custom language spec file**: Hand-written authoritative description of language quirks, gotchas, and idioms — not auto-generated docs
2. **Lazy-loaded API docs**: Full API documentation for all 850+ Godot classes, but loaded on-demand (not pre-loaded into every context) — aligns with Tool Search Tool / defer_loading patterns
3. **Quirks database**: Separate file of common LLM mistakes in this language (Python idioms that compile but behave wrong in GDScript)

**Why this is a transferable pattern:**
- Any niche domain (GDScript, Rust async lifetimes, Solidity, Assembly) with thin LLM training data benefits from this approach
- The three-component structure (spec + lazy API + quirks db) is a repeatable template
- Directly applicable to our game development work: GDScript is used in our Godot games pipeline
- The "quirks database" concept is novel — distinct from documentation, it catalogs model-specific failure modes

**Relationship to existing:**
- Skills architecture: This IS a skill — but with a specific structural pattern we haven't formalized
- Library/techniques: No existing pattern for "thin training data compensation"

**Score estimate**: 73/100 — APPROVED (document as technique)
- Integration complexity: 75 (document pattern; no installation required)
- Token efficiency: 70 (lazy loading component saves tokens)
- Capability expansion: 75 (novel domain-specific accuracy improvement)
- Maintenance: 80 (pattern documentation, zero ongoing burden)
- Community validation: 60 (Show HN, HN discussion, moderate validation)

**Recommended action**: Document as technique in `library/techniques/thin-training-data-compensation-2026-03-21.md`. Evaluate whether our Godot games project would benefit from adopting the godogen skill directly.
