## Novel Discoveries (6)

### 1. Advisor Tool — Executor+Advisor Mid-Generation Consultation
- **Type**: Technique (API feature)
- **Source**: https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool
- **Priority**: HIGH
- **Summary**: Official Anthropic API beta feature (`advisor-tool-2026-03-01`). Pairs a fast executor model (Haiku 4.5 or Sonnet 4.6) with Opus 4.6 as an in-request advisor — within a single `/v1/messages` call. When the executor invokes the advisor, the full transcript is forwarded server-side; Opus produces 400–700 token strategic guidance; executor continues. Distinct from all existing multi-model patterns: no extra round trips, no separate agent invocations, no task delegation. Benchmarked for coding agents and computer use. Announced April 9, 2026. Sonnet+Opus-advisor ≈ full-Sonnet quality at lower cost for coding tasks.
- **File**: `pipeline/evaluation/pending/20260414-advisor-tool.json`

### 3. Claude Managed Agents — Cloud Agent Harness (Beta)
- **Type**: Technique (official platform feature)
- **Source**: https://platform.claude.com/docs/en/managed-agents/overview
- **Priority**: HIGH
- **Summary**: Official Anthropic cloud-hosted containerized agent execution environment. Agents run in isolated containers with pre-installed tools, persistent environments, and lifecycle management via API. Sub-features: outcomes (task completion tracking), multiagent (agent-to-agent communication), memory (research preview). Fills the gap between local Task subagents (short-lived, session-bound) and external agent platforms. Most relevant for long-running external automation (minutes/hours) and multi-agent pipelines that outlive sessions. Beta. API key required.

### 4. PreCompact Hook Blocking + Background Plugin Monitors (v2.1.105)
- **Type**: Technique (registry update — two v2.1.105 features)
- **Source**: https://github.com/anthropics/claude-code/releases (v2.1.105, ~2026-04-13)
- **Priority**: MEDIUM
- **Summary**: Two v2.1.105 additions: (1) `PreCompact` hook — runs before context compaction, can block the operation by returning non-zero exit; enables custom pre-compact validation or state preservation. Distinct from `PostCompact` (already in registry). (2) Background plugin monitors — plugins can now register persistent monitor processes via a `monitors` field in their manifest; these run as daemons alongside the session. Enables event-driven plugin behavior without polling.
