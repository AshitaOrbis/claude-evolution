## Novel Discoveries

### 1. Claude Code Routines — Cloud-Persistent Agentic Automation
**File**: `pipeline/evaluation/pending/20260415-claude-code-routines.json`
**Priority**: HIGH
**Type**: technique

Official Anthropic research preview (April 14, 2026). Save a routine (prompt + repo + connectors) once; runs autonomously on Anthropic cloud infrastructure via three trigger types:
- **Schedule**: cron-style, no local session required
- **API endpoint**: each routine gets its own POST endpoint + auth token
- **GitHub webhook**: auto-session per event (PR opened, push, etc.)

Connectors: Gmail, Slack, Linear, Google Drive, MCP-compatible services. Quota: ~15 runs/day on Pro/Max plan.

**Why novel**: Existing `/loop` and `CronCreate` are explicitly session-scoped — they stop when the session closes. Routines persist on Anthropic infrastructure independently. GitHub event triggers and API-callable endpoints are entirely new capabilities.

**Integration relevance**: Could replace the `cron + claude -p` heartbeat pattern for simpler automations. The 15/day quota limits high-frequency use but suits: nightly repo sweeps, PR review automation, GitHub issue triage.

### 3. context-mode — PostToolUse Hook Output Sandboxing (98% Context Reduction)
**File**: `pipeline/evaluation/pending/20260415-context-mode-posttooluse-sandbox.json`
**Priority**: HIGH
**Type**: skill

Community tool (7.2k stars, 501 forks, created Feb 2026, `github.com/mksglu/context-mode`). Uses PostToolUse hooks to intercept tool outputs before they enter the context window — routes raw data to filesystem, injects only compact summaries.

- **Benchmark**: 315 KB → 5.4 KB (98% reduction on heavy outputs)
- **Targets**: curl responses, Playwright snapshots, grep dumps
- **Claude Code support**: All 5 hook types active; compaction snapshots at PreCompact; state restore after `--continue`
- **License**: Elastic License 2.0 (free to use/modify; no managed service resale)

**Why novel**: `maxResultSizeChars` truncates data (lossy). context-mode sandboxes full data to disk and injects only a summary (lossless with retrieval). No existing capability does post-execution output interception.

**Caution**: 98% reduction applies to heavy-output workflows; typical coding sessions may see lower gains. Hook overhead per tool call needs benchmarking.

### 4. ARIS /research-wiki + /meta-optimize — Self-Optimizing Research Knowledge Base
**File**: `pipeline/evaluation/pending/20260415-aris-research-wiki-meta-optimize.json`
**Priority**: MEDIUM
**Type**: technique

From `github.com/wanshuiyin/Auto-claude-code-research-in-sleep` (AAAI 2026 validated). Two distinct patterns:

**`/research-wiki`** (April 8): Persistent cross-session knowledge base with typed relationships (paper→idea→experiment→claim). Failed ideas become anti-repetition memory — future sessions avoid repeating dead ends.

**`/meta-optimize`** (April 5): Passive hook-based self-improvement. Logs skill invocations + failures via Claude Code hooks, then proposes SKILL.md improvements through a reviewer agent pattern. No explicit metrics/datasets required — uses usage logs as signal.

**Why novel**:
- vs. DSPy Prompt Optimizer: requires explicit metrics/datasets; meta-optimize uses passive usage logs
- vs. Context Librarian: session archive only; wiki has typed cross-session relationships
- `/meta-optimize` pattern is directly applicable to claude-evolution's own skill optimization system

**Domain note**: Primary use case is ML research, but both patterns generalize.
