## Novel Discoveries

### 1. MCP `--channels` Push Messaging (v2.1.80) ⭐

**Type**: technique (version feature)
**Priority**: HIGH
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2180-2026-03-19-evaluation.json`

MCP servers can now push messages to Claude sessions using a new `--channels` flag. This changes the fundamental MCP communication model from request-response to **bidirectional**. Previously, Claude always initiated MCP interactions (calling tools). Now MCP servers can initiate communication — enabling:

- Push notifications when background tasks complete
- Live data subscriptions (streaming rate limit alerts, build status)
- Event-driven agent triggers without polling

Currently a **research preview** — no immediate integration action needed, but architecturally significant. Monitor for stable release. This fills a real gap: heartbeat cron jobs currently poll for completion; --channels would enable push-on-done instead.

**Score**: 81.25/100 — APPROVED (research preview, defer full integration until stable)

### 2. `rate_limits` Statusline Field (v2.1.80)

**Type**: technique (version feature)
**Priority**: MEDIUM
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2180-2026-03-19-evaluation.json`

The statusline script now has access to a `rate_limits` field exposing Claude.ai usage on 5-hour and 7-day windows:

```json
{
  "rate_limits": {
    "hour5": {"used": 42, "limit": 100},
    "day7": {"used": 318, "limit": 1000}
  }
}
```

**Immediate application**: Update the heartbeat statusline script to surface rate limit proximity. When `hour5.used / hour5.limit > 0.85`, heartbeat should back off or skip expensive discovery runs. This is more reliable than post-hoc "rate limit exceeded" errors.

**Score**: Part of v2.1.80 bundle (81.25/100) — APPROVED

### 3. `source: 'settings'` Inline Plugin Declarations (v2.1.80)

**Type**: technique (version feature)
**Priority**: LOW-MEDIUM
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2180-2026-03-19-evaluation.json`

Plugins can now be declared inline in `settings.json` without the marketplace UI:

```json
{
  "plugins": [
    {"source": "settings", "name": "my-plugin", "commands": [...]}
  ]
}
```

Enables version-controlled plugin configuration (plugins tracked in `settings.json` alongside hooks, permissions, etc.). Useful when distributing Claude Code configurations across machines via Syncthing — plugins travel with the config file rather than requiring manual marketplace installation.

**Score**: Part of v2.1.80 bundle — APPROVED

### 4. `effort` Frontmatter for Skills and Slash Commands (v2.1.80, IMPROVEMENT)

**Type**: technique (version feature — IMPROVEMENT of existing v2.1.78 capability)
**Priority**: LOW
**Evaluation file**: `pipeline/evaluation/pending/claude-code-v2180-2026-03-19-evaluation.json`

v2.1.78 added `effort:` frontmatter to agents. v2.1.80 extends this to **skills and slash commands**. Add `effort: low` to cost-sensitive skills (discovery routing, simple lookups) to reduce compute allocation:

```yaml
---
name: model-router
effort: low
---
```

Low-friction improvement. Discovery/routing skills (`model-router`, `mcp-search-framework`) are good candidates for `effort: low` since they do simple lookups, not complex reasoning.

**Score**: Part of v2.1.80 bundle (IMPROVEMENT, not standalone novel) — APPROVED
