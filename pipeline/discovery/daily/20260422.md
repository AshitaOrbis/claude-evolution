## Novel Discoveries (4 new files saved to pipeline/evaluation/pending/)

### 1. bfs + ugrep Native Glob/Grep Replacement (v2.1.117)

**File**: `bfs-ugrep-native-tool-optimization-v2.1.117.json`  
**Type**: technique  
**Preliminary score**: 70-80  

In v2.1.117, the Glob and Grep built-in tools on macOS/Linux now use embedded `bfs` (faster filesystem traversal) and `ugrep` (parallel grep) instead of the previous ripgrep backend. Automatic — no configuration. Most existing Grep patterns are compatible, but ugrep has edge-case differences from ripgrep regex extensions that should be validated.

**Why it matters**: Every Glob and Grep call in every session is now faster. Potential behavioral edge cases in custom regex patterns.

### 2. Agent Frontmatter mcpServers for --agent Sessions (v2.1.117)

**File**: `agent-frontmatter-mcpservers-v2.1.117.json`  
**Type**: technique  
**Preliminary score**: 75-85  

Agents can now declare `mcpServers:` in their frontmatter and those servers load when the agent runs via `claude --agent agent-name` (main-thread mode). Previously, agent-level MCP declarations only worked in subagent/Task tool mode. Companion to the v2.1.116 improvement that extended frontmatter `hooks:` to `--agent` mode.

**Why it matters**: Enables fully self-contained agents that bundle their own MCP server dependencies — evolution pipeline agents could declare event-bus MCP in frontmatter rather than requiring global config.

### 3. Default Effort Raised to high for Pro/Max on Opus 4.6/Sonnet 4.6 (v2.1.117)

**File**: `default-effort-max-plan-raised-v2.1.117.json`  
**Type**: technique (registry correction)  
**Preliminary score**: 78-85  

v2.1.117 raised the default effort for Pro and Max plan subscribers from `medium` to `high` on Opus 4.6 and Sonnet 4.6. **Registry correction required**: the existing v2.1.94 entry explicitly states "Max plan users unaffected" — that is now outdated. Direct impact: heartbeat and `claude -p` runs without explicit `--effort` will use `high` effort, increasing compute cost per run.

**Action items**: (1) Update registry v2.1.94 entry. (2) Evaluate adding `--effort medium` to cost-sensitive heartbeat invocations. (3) Verify empirically with `claude -p --print-config`.

## Other Notable v2.1.117 Changes (registry-only, no new pending files)

These v2.1.117 changes are worth noting but don't warrant new pending files:

- **OAuth token reactive refresh**: Plain-CLI sessions now refresh on 401 instead of dying with "Please run /login". Automatic fix.
- **MCP concurrent connect default**: Faster startup when both local and claude.ai MCPs configured. Automatic.
- **`/resume` summarization offer**: When `/resume` encounters a stale, large session, it now offers to summarize before re-reading (matching `--resume` behavior). UX improvement.
- **`cleanupPeriodDays` expansion**: Retention sweep now covers `~/.claude/tasks/`, `~/.claude/shell-snapshots/`, `~/.claude/backups/` in addition to existing dirs.
- **OTEL command tracking**: `user_prompt` events now include `command_name` and `command_source` for slash commands; cost events include `effort` attribute.
- **WebFetch hanging fix**: Fixed WebFetch hanging on very large HTML pages — relevant for heartbeat research runs.
- **Subagent malware warning false positive**: Fixed — subagents running different model than main agent no longer incorrectly flag file reads.
- **Idle re-render loop on Linux**: Fixed memory growth regression on requiem (native Linux).
