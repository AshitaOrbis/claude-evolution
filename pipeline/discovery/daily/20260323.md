## Novel Discoveries

### 1. Context Mode MCP — Tool Output Compression (98% reduction) ⭐⭐

**Type**: mcp_server
**Priority**: HIGH
**Redundancy**: NOVEL — registry has Cloudflare Code Mode (schema compression), but this is output compression
**File**: `pipeline/evaluation/pending/context-mode-mcp-output-compression-2026-03-23.json`
**Source**: https://github.com/mksglu/claude-context-mode (stars unconfirmed; HN Show HN post, Anthropic issues tracker)

An MCP server that intercepts large tool outputs (Playwright snapshots, GitHub API responses, logs) before they enter the context window, processing them in isolated sandboxes and returning compact references + BM25-searchable SQLite index. Demonstrated: 315 KB → 5.4 KB (98% reduction). Extends usable session time from ~30 minutes to ~3 hours.

**Mechanism**: Hooks into Claude Code's tool output path via PostToolUse hooks. Processes raw output in sandboxes. Builds SQLite FTS5 with BM25 ranking for search. Returns summary + reference ID instead of raw content.

**Relation to existing**:
- Cloudflare Code Mode (in registry): Compresses tool SCHEMA definitions → 80% token reduction on API surface
- Context Mode: Compresses tool OUTPUT responses → 98% token reduction on runtime responses
- These are complementary, not redundant

**Key concern**: No star count confirmed. HN submission but community size unknown. MIT license confirmed.

### 2. PAL MCP (formerly Zen MCP Server) — Multi-Provider Abstraction Layer ⭐⭐

**Type**: mcp_server
**Priority**: MEDIUM
**Redundancy**: IMPROVEMENT over existing Codex+Gemini dual integration
**File**: `pipeline/evaluation/pending/pal-mcp-server-provider-abstraction-2026-03-23.json`
**Source**: https://github.com/BeehiveInnovations/zen-mcp-server (rebranded to PAL; ~10.8k stars per scriptbyai.com resource list)

PAL (Provider Abstraction Layer), formerly Zen MCP Server, enables Claude Code to call Gemini, OpenAI, Grok, OpenRouter, Ollama, and custom models from within a single conversation. Claude stays in control — PAL is invoked when Claude determines a task benefits from another model's perspective (e.g., code review → Gemini Pro, fast synthesis → Flash).

**Why it matters**: Our current setup has Codex (GPT-5.4) and Gemini as separate MCPs. PAL unifies multi-model calls under one MCP with model-alias support, provider fallback chains, and conversation threading across models.

**Redundancy check**:
- We have: `mcp__codex__codex` (GPT-5.4) + `mcp__gemini-cli__ask-gemini` (Gemini 3.1 Pro)
- PAL adds: Grok, OpenRouter, Ollama, custom models — plus unified interface
- This is an IMPROVEMENT (broader coverage, single MCP vs two) but introduces duplication with existing integrations
- COMPARISON evaluation warranted before adopting

**Community validation**: 10.8k stars is strong. Active maintenance (renamed and actively developed in 2026).

**Type**: feature (Claude Code built-in)
**Priority**: MEDIUM
**Redundancy**: IMPROVEMENT over existing Effort Controls entry (API-only, frontmatter-only in registry)
**File**: `pipeline/evaluation/pending/effort-slash-command-ultrathink-2026-03-23.json`
**Source**: https://www.jdhodges.com/blog/how-to-change-claude-code-effort-levels-in-vs-code-effort/ + releasebot.io

Two interactive effort control features not in registry:
- `/effort` slash command (v2.1.76): Cycles through Low/Medium/High/Max reasoning levels per session, visible in the logo/spinner

The registry has "Effort Controls (API)" and `effort` frontmatter for agents/skills (v2.1.78+), but neither the interactive slash command form nor the `ultrathink` per-turn override. These are different interfaces for the same underlying parameter — useful for interactive sessions vs programmatic automation.

**Integration**: Registry update only. Built-in feature, no configuration required.
